# Authoring guide: settlens.com

The site is generated by `site/build.js` (Node stdlib only). You write one JavaScript module per
page in `site/src/pages/`; the build wraps it in the layout, adds SEO and structured data, checks it
and writes static HTML to `site/public/`.

```bash
node site/build.js                         # strict build into site/public (what ships)
node site/build.js --allow-missing=pending # while other pages are still being written (never ship)
npm run site:dev                           # same drafting build (pending routes tolerated), then serve on http://127.0.0.1:8080
node --test test/site.test.js              # site and server tests
npm run quality                            # full suite with coverage thresholds
```

Look at `/styleguide` (built from `pages/styleguide.js`) to see every component rendered.

## 1. Page contract

```js
// site/src/pages/docs/cli.js
export const meta = {
  path: "/docs/cli",                       // required: lowercase, hyphenated, no trailing slash
  title: "CLI reference",                  // required: <title> becomes "CLI reference | Settlens"
  description: "Every Settlens command, option and exit code, with examples for passive scans, CI gates, monitoring, evidence and the MCP server.", // required: 120-160 chars
  section: "docs",                         // required: free label used by ctx.inSection() and related links
  lastmod: "2026-10-13",                   // required: YYYY-MM-DD, used in sitemap and "Last updated"
};

export default function render(ctx) {
  return ctx.html`<p>…</p>`;               // the inner HTML of <main> (or the layout body, see §2)
}
```

Optional `meta` fields:

| Field | Use |
|---|---|
| `heading` | Visible `<h1>` text for article/docs layouts when it should differ from `title`. |
| `label` | Short name for nav-like places: breadcrumbs, docs sidebar, hub cards. |
| `lede` | Intro under the `<h1>` in article/docs layouts (defaults to `description`). |
| `layout` | `"page"`, `"article"` or `"docs"` (defaults: `/docs*` → docs, `/blog/*` and `/learn/*` → article, else page). |
| `ogType` | `"website"` or `"article"` (article layout defaults to article). |
| `datePublished`, `dateModified` | `YYYY-MM-DD`. Required `datePublished` on blog posts. |
| `author` | `"Name"` or `{ name, url }`. Required on blog posts. |
| `tags` | Array of strings. Required (non-empty) on blog posts; shown as pills, in RSS and `article:tag`. |
| `related` | Array of paths shown as "Related reading" in the article layout (default: newest pages of the same section). |
| `order` | Number used to sort `ctx.children()` and `ctx.inSection()` (then by label/title). |
| `icon` | Icon name used by `toCard(page)` in hub grids. |
| `jsonLd` | Extra schema.org node or array of nodes added to the page `@graph` (see §6). |
| `schemaType` | Type of the layout's `#webpage` node on page-layout pages: `ContactPage`, `AboutPage`, `CollectionPage`… (default `WebPage`). |
| `noindex` | `true` → `noindex` robots meta, excluded from sitemap, RSS, llms.txt, hubs. |
| `priority`, `changefreq` | Sitemap hints (`0..1`, `weekly`, …). |
| `breadcrumbs` | `false` to hide, or `[{ name, path }]` to override the automatic trail. |
| `toc` | `false` hides the "On this page" table of contents in article/docs layouts. |
| `summary` | Answer-first "In short" text, 120-320 characters of plain text: rendered by the layout (§5 Answer blocks), JSON-LD `abstract`, the page's line in `llms.txt` and the top of its `.md`. `--require-summary` makes it mandatory on indexable, non-legal pages. |
| `sources` | `[{ title, url, publisher? }]`, absolute `https` URLs of primary sources: the "Sources" section, JSON-LD `citation` and the `.md`. Reserved ids: a body must not use `in-short` or `sources`. |
| `scripts` | `["tools"]` loads the fingerprinted `site/src/assets/tools.js` (deferred) on that page only; the build fails if the file is missing. |

Every indexable page is also published as Markdown at `<path>.md` (`/index.md` for `/`), converted
from its rendered body, and listed in `llms.txt`; `llms-full.txt` concatenates them. A page's Open
Graph image is `site/src/assets/og/<slug>.png` when it exists (`node site/tools/og.mjs` renders them),
else the site default.

Route mapping: `/a/b` → `public/a/b/index.html`, `/` → `public/index.html`, `/404` → `public/404.html`.
Canonical URL = `https://settlens.com` + path. Always link with absolute paths and no trailing slash
(`/docs/cli`, never `docs/cli`, `/docs/cli/` or `/docs/cli.html`). File names should mirror the
path (`pages/docs/cli.js`, `pages/docs/index.js`); files and folders starting with `_` are ignored.

The build fails (exit 1, nothing written) on: duplicate paths; missing title/description/section/
lastmod; description outside 120-160 chars; `<title>` over 60 chars; zero or several `<h1>`;
broken internal links or anchors; trailing-slash links; invalid JSON-LD; any `style=` attribute,
`<style>` element, inline `<script>` (other than `application/ld+json`), `on*=` handler or
`javascript:` URL (the CSP forbids them); any absolute or protocol-relative resource URL (`src`,
`srcset`, stylesheet/preload/icon `<link>`: the CSP only loads same-origin files); duplicate ids;
`<img>` without `alt`; more than one FAQ block per page; blog posts without `datePublished`,
`author` and `tags`.

## 2. Layouts and the `<h1>`

- **page**: your render output is `<main>`. You own the `<h1>`, normally through `hero()`. Pages two
  levels deep or more (`/product/ci`) get automatic breadcrumbs above your content.
- **article** (`/blog/*`, `/learn/*`): the layout renders breadcrumbs, the `<h1>` (`heading ?? title`),
  the lede, a meta line (published/updated dates, reading time, author), tag pills, a sticky table of
  contents built from your `<h2>`/`<h3>`, "Related reading" and a closing call to action. Your render
  returns the article body only: start with a paragraph, structure with `<h2>`/`<h3>`, **no `<h1>`**.
- **docs** (`/docs`, `/docs/*`): sidebar of every docs page grouped by `site.docsNav`
  (`data/site.js`), breadcrumbs, `<h1>`, lede, table of contents, "Last updated" and previous/next
  links. Body only, **no `<h1>`**. Docs pages not listed in `site.docsNav` appear under "More".

Headings `<h2>`/`<h3>` without an `id` get one from their text (`"How it works"` → `how-it-works`),
so `#how-it-works` links work. Give an explicit `id` when you link to a heading from elsewhere.

## 3. The `ctx` object

`render(ctx)` receives every component below plus:

| Member | Description |
|---|---|
| `html`, `raw`, `escape`, `cx`, `slugify`, `stripTags`, `icon`, `ICON_NAMES` | Templating helpers (§4). |
| `site` | `data/site.js`: name, origin, version (CLI `VERSION` from `src/constants.js`), email, legal data, nav, footer, docsNav. |
| `page` | The current page record: your `meta` plus `url`, `layout`, `documentTitle`, `readingMinutes`. |
| `pages` | All page records except the 404, sorted by path. |
| `find(path)` | One page record, or `undefined`. |
| `children(path)` | Indexable direct children of `path` (`children("/docs")` → `/docs/quickstart`, …), sorted by `order` then label. |
| `inSection(name)` | Indexable pages whose `meta.section` equals `name`. |
| `posts({ tag, limit })` | Blog posts, newest first. Each has `datePublished`, `tags`, `readingMinutes`. |
| `url(path)` | Absolute URL (`https://settlens.com/path`). |

**Hubs list their children from data, never by hand:**

```js
export default function render(ctx) {
  return ctx.html`${ctx.hero({ title: "Documentation", lede: "…" })}
${ctx.section({ title: "Guides", body: ctx.cards(ctx.children("/docs").map(ctx.toCard), { columns: 3 }) })}`;
}
```

Blog index: `ctx.postList(ctx.posts())`. A new child page then appears in its hub, the sitemap,
RSS (blog) and llms.txt automatically.

## 4. Templating

```js
ctx.html`<p>${userText}</p>`         // interpolations are HTML-escaped
ctx.html`<ul>${items.map((i) => ctx.html`<li>${i}</li>`)}</ul>`  // arrays are joined; nested html`` is kept
ctx.raw("<svg …>…</svg>")            // trusted markup you wrote; never for external text
ctx.html`${cond ? ctx.html`<p>x</p>` : ""}`  // null/false/true render nothing
ctx.cx("card", featured && "card--featured")  // class names
ctx.icon("check")                     // decorative SVG; ctx.icon("check", { label: "Passed" }) for meaningful icons
```

Component text arguments are escaped. Where a component accepts "string or html", pass
`` ctx.html`…` `` to include markup (links, `<code>`). Plain strings in `body`/`a` fields become a
paragraph. Icons available: `arrow-right arrow-left chevron-right chevron-down check x minus menu
info alert x-circle check-circle shield shield-check terminal copy search branch activity seal
signature chip book file lock key mail rss external layers clock`.

## 5. Components

Every example below is rendered on `/styleguide`.

### Page structure

```js
hero({ title, lede, actions: [{ label, href, icon }], aside, note, align: "split"|"center" })
// The page <h1>. First action is primary, the rest secondary. `aside` (inspector, terminal, diagram…) makes
// it two columns, with a faint measuring grid behind the aside.
hero({ title: "Prove your x402 endpoints fail closed.", lede: "…", actions: [{ label: "Request a pilot", href: "/contact", icon: "arrow-right" }, { label: "Read the docs", href: "/docs" }], aside: terminal({ … }) })

section({ title, lede, body, id, tone: "default"|"raised", width: "default"|"narrow"|"wide", align: "start"|"center", actions })
// A band with an <h2>. Use tone "raised" to alternate bands. `id` makes it linkable (#id).
// Section actions are all secondary: one primary button per band (the hero's first action, the CTA band's
// first action). Pass variant: "primary" on an action only when that section is the page's main ask.
// Blocks stacked in one body (and in split() columns or a hero aside) are spaced evenly by the CSS:
// pass them side by side, never add spacer elements or margins.
section({ id: "how-it-works", title: "How it works", lede: "…", body: steps([…]) })

container(body, { width })            // gutter + max width for content outside section()
split({ main, aside, reverse })       // two columns ≥ 56rem, stacked below
prose(body)                           // long-form typography (lists, code, blockquote) at a 68ch measure
cta({ title, body, actions })         // closing band with an <h2>; one per page; first action primary
cta({ title: "Assess one payment surface first", body: "…", actions: [{ label: "Request a pilot", href: "/contact" }, { label: "See pricing", href: "/pricing" }] })
```

### Content blocks

```js
cards(items, { columns: 2|3|4, headingLevel: 3 })    // boxed tiles; with href the whole tile is a link
cards([{ icon: "search", title: "Assess", body: "Passive scan of the 402 handshake…", href: "/product/assess", tag: "Passive" }])

featureGrid(items, { columns, headingLevel })        // unboxed features with hairline rules; optional href + linkLabel
featureGrid([{ icon: "lock", title: "No custody", body: "Settlens never holds funds, wallets or payment keys." }])

steps(items, { headingLevel })                       // ordered procedure (numbered)
steps([{ title: "Scan passively", body: "…" }, { title: "Gate in CI", body: ctx.html`<p>Fail at <code>--fail-on high</code>.</p>` }])

callout({ tone: "info"|"note"|"success"|"warning"|"danger", title, body })
callout({ tone: "warning", title: "Authorized testing only", body: "Use --active --authorized only with the owner's written approval." })

stats(items) / stat(item)                            // verifiable facts only, never invented metrics
stats([{ value: "0", label: "Wallets or payment keys required" }, { value: "3", label: "Report formats", detail: "JSON, HTML and SARIF" }])

keyValues([{ term, value }])                         // labelled facts (legal notice, contact)
keyValues([{ term: "SIREN", value: ctx.site.legal.siren }])

badge(text, { tone: "neutral"|"accent"|"success"|"warning"|"danger"|"info" })   // status label
pill(text, { tone })                                 // rounded tag
button({ label, href, variant: "primary"|"secondary"|"ghost", size: "sm", icon, type })  // <a> with href, else <button>
```

### Product visuals

Real product output in one shared chrome (`panel`): a titled bar, a gradient edge and the panel shadow.
Feed them only real data: a build-time MCP call (`evaluate()` from `pages/mcp.js`) or a recorded run, and
say which in the caption. They are real text (not images), so they are read in order and indexed.

```js
panel({ title, meta, body, caption })
// The shared chrome; body is a string (one paragraph) or html``. Use it for any other short, real output.
inspector({ title, meta, request: { label, call, response }, rows: [{ field, value, check, status: "pass"|"warn"|"fail" }], decision: { value, tone, reason }, caption })
// One payment request checked field by field (the home hero). An unknown status fails the build. Long check
// ids break after "." and "_". Put the failing row last: the one authored animation scans the rows, ticks
// each check, then settles the decision badge (about 2.7 s, once, never with reduced motion).
inspector({ title: "evaluate_payment_requirements", meta: "12 of 13 checks pass", request: { label: "Agent requested", call: "GET 127.0.0.1:4402/premium", response: "402 PAYMENT-REQUIRED" }, rows: [{ field: "scheme", value: "exact", check: "policy.scheme", status: "pass" }], decision: { value: "do_not_pay", tone: "danger", reason: "…" }, caption: "…" })
reportPreview({ file, meta, mode, target, summary: { pass, fail, warn, skip }, findings: [{ id, severity, message }], facts: [{ term, value }], caption })
// A Settlens JSON report at a glance, from a recorded run. severity critical|high|medium|low|info picks the badge tone.
verdicts({ title, meta, items: [{ decision, tone, when, detail }], caption })
// One request evaluated under several policies: a decision chip column, then the condition and the reason.
```

### Answer blocks

The layouts render these from page metadata; call them directly only on the styleguide.

### Code, data and diagrams

```js
codeBlock({ code, lang: "shell"|"json"|"yaml"|"js"|"http"|"text", title, copy: true, wrap: false })
// Language label + copy button (JS only). Light token colouring for shell, JSON and YAML.
// wrap: true breaks long lines instead of scrolling: use it for base64 headers, minified JSON, CSP
// headers and one-line install commands in narrow columns (the copy button still copies the exact text).
// Do not prefix shell commands with "$ " (the copy button copies the text as is).
codeBlock({ lang: "shell", title: "Passive scan", code: `settlens scan https://merchant.example/api/data \\
  --expect-network eip155:8453 --max-amount 10000` })

terminal({ title, lines: [{ kind: "cmd"|"cont"|"out"|"pass"|"fail"|"warn"|"skip"|"muted", text }], replay: true })
// A CLI transcript (prompt added to "cmd"; "cont" continues a command). Replays line by line once
// visible unless reduced motion is on; a terminal in the hero, or already scrolled past, shows at once. Only real output from the CLI (run the demo: npm run demo:server).

table({ caption, head: ["Code", "Meaning"], rows: [["0", "…"], …], rowHeaders: true, numeric: [columnIndex] })
// A row header that is one token of at most 24 characters (an ID such as PAY-01) never wraps, so plain
// ASCII hyphens are fine in IDs. Code in tables does not break mid-word: wide tables scroll instead.
// Below 48rem each row stacks into a card: the row header, then each cell under its column header.
comparisonTable({ caption, columns: ["Behavior", "Passive scan", "Active probe"], rows: [{ label, values: [false, "One invalid signature"] }], highlight: 1 })
// true → check (labelled "Yes"), false → dash ("No"), strings as text. `highlight` is the column index to tint.

diagram({ svg, svgNarrow, label, caption, size: "default"|"wide" })   // see §7
// svgNarrow (optional): a stacked version of the same diagram, shown instead of svg below 40rem.
// Without it, a narrow screen scrolls the diagram sideways (an edge shadow signals the hidden part).
```

## 6. Structured data

Every page gets one JSON-LD `@graph` in `<head>`: `Organization` (`#organization`), `WebSite`
(`#website`) and a page node: `WebPage`, `Article`, `BlogPosting` (blog) or `TechArticle` (docs),
with dates, author, image and keywords from `meta`. `breadcrumbs()` and `faq()` add their own
`BreadcrumbList` / `FAQPage` blocks. Add anything else through `meta.jsonLd`, referencing the shared
nodes by `@id`:

```js
export const meta = {
  // …
  jsonLd: {
    "@type": "SoftwareApplication",
    name: "Settlens CLI",
    applicationCategory: "SecurityApplication",
    operatingSystem: "Node.js 20+",
    softwareVersion: "0.5.0",   // import { VERSION } from "../../../src/constants.js" rather than hard-coding
    publisher: { "@id": "https://settlens.com/#organization" },
  },
};
```

One description per `@id` across the whole site. When several pages define the same `@id` (for
example `https://settlens.com/#software`), the build merges them into one canonical node and every
one of those pages emits it; a property set to two different values on two pages fails the build.
Share a node by reusing the defining page's object (`jsonLd: homeMeta.jsonLd`) or list it by
reference, `jsonLd: { "@id": "https://settlens.com/#software" }`, to emit the canonical node. Never
redefine the layout's `#organization`, `#website` or `#webpage` nodes; reference them by `@id`.

Never add `offers` with invented prices, `aggregateRating`, or `review` nodes.

## 7. Diagrams

Inline SVG only (no images of text, no external files). Draw at `viewBox="0 0 720 H"` with
`width`/`height` attributes, labels ≥ 13 units, and the classes below so colours follow the tokens.
No `style` attributes, no `<style>`, no `id`s or `<marker>`s (draw arrowheads as short paths), and
always pass `label`: a sentence describing what the diagram shows. Narrow screens scroll the canvas.

| Class | Element |
|---|---|
| `d-node`, `d-node--accent` | Boxes (`<rect rx="10">`). |
| `d-title`, `d-text`, `d-label` (mono, for protocol data), `d-label--accent`, `d-note`, `d-note--blue` | `<text>`. |
| `d-msg`, `d-msg--accent`, `d-msg--blue`, `d-line`, `d-accent` | Lines and arrows. |
| `d-head`, `d-head--accent`, `d-head--blue` | Arrowheads (`<path d="M350 102l8 6-8 6">`). |
| `d-life` | Dashed lifelines. |
| `d-zone`, `d-zone--blue` | Dashed highlight areas. |

See `FLOW_SVG` in `pages/styleguide.js` for a complete sequence diagram.

## 8. Writing rules

- English, US spelling, sentence-case headings. Concise and concrete: say what is checked, how and
  what the result proves. No hype ("revolutionary", "bulletproof", "military-grade", "AI-powered").
- Every capability claim must match the truth table below. When unsure, leave it out.
- No fake customer logos, testimonials, case studies, user counts, uptime or performance figures.
  No invented prices: pricing copy comes from the brief. Mark illustrative data as illustrative.
- Real CLI commands and output only (`node src/cli.js --help`, `npm run demo:server`).
- Distribution: the code is in a **private** repository and the CLI (Node.js 20+) is available to
  pilot participants. Never write `npm install settlens`, "open source" or "on npm".
- Settlens is not a blockchain, has no token and never custodies funds, wallets or payment keys.
  Signed evidence does use a key: pilots sign attestations with an ed25519 signing key (`keygen`),
  so never write "no keys", "keyless" or "no private keys".
- Link to the docs page that substantiates a claim. Prefer "Settlens checks X" over "Settlens
  guarantees X". Reports are evidence of observed behavior, not certification or legal advice.
- Old site text lives in `site/src/legacy/` (read its README for claims that must not be reused).

### Capability truth table (the only claims allowed)

- **Passive scan** of an x402 V2 paid resource (default): HTTP 402 status; `PAYMENT-REQUIRED`
  header present and Base64 JSON decodable; validation with the official `@x402/core` 2.28.0 SDK;
  V2 core shape; `resource.url` bound to the tested URL; per-requirement validation (scheme, CAIP-2
  network, positive atomic amount, asset, `payTo`, `maxTimeoutSeconds` window); duplicate
  requirements; HTTPS; redirects are not followed (flagged); bounded response body; drift and
  stability across repeated identical requests; local policy (schemes, networks, `payTo`
  recipients, assets, `maxAmount`).
- **Active probe**, only with `--active --authorized --authorization-ref`: sends one intentionally
  invalid `PAYMENT-SIGNATURE` and asserts the resource fails closed and the facilitator `/verify`
  rejects it. Never calls `/settle`, never moves funds, needs no wallet or private key.
- **Facilitator scan**: `GET /supported` schema, V2 capability, signer metadata and requirement
  coverage, HTTPS, content type, duplicate kinds.
- **verify-payment** (offline, no RPC): EIP-3009 / EIP-712 signer recovery for the `exact` EVM
  scheme (domain rebuilt from `requirement.extra` name/version + asset + chain id), binding
  (`payTo`, value, asset), amount and strict `validAfter < now < validBefore` freshness (`--now`
  sets the check time); Solana ed25519 check of every signer slot for legacy and versioned
  transactions, empty slots (the fee payer before settlement) reported as pending. Complete
  Solana payment terms also request the supported static SPL TransferChecked profile;
  partial terms are refused, and absent terms explicitly mean signatures only. It does **not**
  check on-chain balances, on-chain nonce use/replay, runtime execution, or settlement.
- **Reports**: JSON with a deterministic SHA-256 integrity block (`settlens-stable-json-v2`; v1
  reports still verify), HTML, SARIF anchored at line 1 of the config file; `verify-report`.
- **Monitor**: baseline (per method and URL) vs current passive scan; alerts for regressions, new
  failing/warning checks and removed checks (coverage lost); optional webhook alert; non-zero exit
  at threshold.
- **Evidence**: ed25519 `keygen` (refuses to overwrite) / `attest` / `verify` (`--expect-key`
  pins the signer) binding a report digest, identity and timestamp; verifiable offline.
- **MCP server** (stdio and `https://settlens.com/mcp`): `evaluate_payment_requirements` answers
  `pay` only when the policy sets `pay_to`, `assets`, `networks` and `max_amount` and an option
  satisfies it; offline verification tools; passive network tools (token-gated remotely).
- **GitHub composite Action**: `fail-on` threshold, `allowed-hosts` for custom headers, SARIF
  output; pinned non-root container image.

## 9. Styling and scripts

- Use component classes; add new styles to `site/src/assets/site.css` with the existing tokens
  (`--space-*`, `--step-*`, `--text*`, `--surface*`, `--accent`, `--edge`, `--tracking-*`…). The
  budgets apply to the built files: minified CSS < 60,000 bytes, `site.js` < 10,000 bytes (it is at
  about 9.9 KB: page-specific code goes in its own file, like `tools.js` for `/tools/*`).
- No inline styles, no inline scripts, no third-party requests of any kind (fonts, analytics,
  embeds, CDNs). The CSP is `default-src 'self'` and will block them. Scripts may set CSS custom
  properties through the CSSOM (`el.style.setProperty`), never a `style` attribute or HTML strings
  (Trusted Types is `'none'`).
- `site/src/assets/site.js` is progressive enhancement only (menu, copy buttons, TOC highlight and
  indicator, pilot form, terminal replay, diagram flows, card light). Every page must work with
  JavaScript disabled.
- **Type.** Inter variable is self-hosted from `src/assets/fonts` (OFL, `LICENSE-Inter.txt`). `build.js`
  fingerprints it and rewrites its URL in the CSS; the layout preloads it; `font-display: optional`
  plus the metric-matched "Inter Fallback" faces keep layout shift at zero. Weights: 400 body, 500 UI,
  600 card and button titles, 650 headings. Tracking comes from `--tracking-display|title|snug`; body
  text stays at 0. Never add font files, third-party fonts or `font-variation-settings` (it disables
  optical sizing). Tabular figures only on pure numbers: Inter's `tnum` also widens spaces and commas.
- **Elevation.** One gradient hairline (`--edge`) or a shadow, never a zero-offset glow as depth.
  `--edge-accent` only on hover, focus or the CTA band. Measuring grids only behind a hero visual or
  inside a diagram canvas. No noise textures, gradient text, glass cards, eyebrows or kickers, coloured
  side borders over 1px, or a second primary button in a band.
- **Motion.** Every `animation` sits inside `@media (prefers-reduced-motion: no-preference)`: finite,
  transform and opacity only (plus `stroke-dashoffset` for diagram packets), never fading text (contrast
  checks must hold mid-animation) and never on the LCP text. Sections are never revealed on scroll. What exists: cross-document view transitions
  (the header and the docs sidebar keep their place, the page crossfades), the inspector moment (one
  per page), micro-interactions (buttons, card edge and light, nav underline, mobile menu, copy check,
  FAQ opening, the TOC indicator) and diagram flows: `site.js` clones each `.d-msg` path into a
  `.d-packet` that travels in document order, two cycles, paused while the diagram is off screen. Draw
  message paths in the direction of the message and in the order they happen.
- Brand files (`site/assets/`) are copied to `/assets/` unchanged. The logo wordmark is outlined
  (Inter 700, opsz 32, kerned SVG paths, no live `<text>`), so it looks the same on every OS.
  `og-image.jpg` (1512×794, quality 82) is the Open Graph image, exported from `og-image.png`
  (re-export it when the PNG changes).
