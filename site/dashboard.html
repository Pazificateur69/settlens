Set up your first endpoint

Each step reflects the saved workspace. Observations never approve themselves; a completed checklist is not a guarantee about payment safety.

    Understand atomic amounts

    Enter an integer maximum in the endpoint policy. Atomic units are the asset's smallest units, not a fiat value. One maximum applies to every allowed asset in its own units; review whether that ceiling is appropriate for each asset.

    This optional calculator uses only the decimals you explicitly choose. Verify the decimals for the exact asset and network yourself. It does not infer them from a name or symbol, round prices, or change your policy.

    Copy the resulting integer into the maximum or price range, then review and save the endpoint policy explicitly. The calculator supports at most 78 output digits.

    Prepare CLI and private CI

    Settlens is supplied through the private pilot repository; it is not published on npm. Use an authorized private checkout with its package-lock.json and Node.js 20.19 or newer. The example CI uses Node.js 24.

    Review configuration
    The configuration contains endpoint names, URLs and policy only. It does not transfer approved references, history, credentials, email delivery settings or the dashboard schedule.
    Download CLI baseline separately to transfer recorded references and observations. This export creates no new approval and excludes delivery jobs. Keep this journal private. Preserve any existing CLI journal before choosing how to migrate it.
    The copy command leaves an existing CLI journal untouched. Without a transferred baseline, monitoring starts with a new observation and you must review and approve a reference separately. CLI monitoring needs a schedule to run repeatedly; downloading files does not run checks or configure CI.
    Example: a manual policy gate in a source repository
    This workflow assumes the supplied Settlens source and downloaded settlens.config.json are available in the runner checkout. It runs a fresh passive policy gate; it does not carry approved-reference drift or a persistent journal.
    For recurring monitoring, adapt examples/monitor-workflow.yml from the private source, seed its protected journal with the reviewed baseline and retain that journal between runs. An absent or expired journal creates a new baseline. See monitoring instructions.
